# PolePilot

**AI-powered infrastructure surveys — live at https://surveyai.live.**

PolePilot is an independently developed project that helps utility survey teams turn field photographs and survey videos into reviewable pole and component records. It combines local YOLO models, component-aware crops, survey rules, human review, and structured exports, presented with an isolated public evaluation experience.

## Try it locally

For the recorded demo, no model weights or database server are needed:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements-demo.txt
$env:LIVE_INFERENCE_ENABLED="false"
$env:WORKSPACE_ENABLED="false"
```

Then start Flask:

```powershell
python app.py
```

Open http://127.0.0.1:5002. The landing page explains the product; `/demo` needs no login or PostgreSQL. Public startup does not load model weights. The 11 unique replay samples contain **actual predictions**, totaling 176 detections, generated by `python scripts/record_samples.py`, with input/model SHA-256 hashes and timestamps. Live sample or image inference is available when dependencies/weights are installed and `LIVE_INFERENCE_ENABLED=true` (the local default). The deployed small-VM profile disables live inference and the full workspace.

The training imagery is described as real field data from Andhra Pradesh. The product is intended for Indian distribution environments; generalization outside that environment has not been established. The homepage shows saved metrics extracted directly from active model checkpoints through `scripts/export_checkpoint_metrics.py`, including pole box mAP@50 of 99.28%, precision 98.57% and recall 98.54%. These are checkpoint-reported model-validation scores, not a verified overall application accuracy. Dataset size and train/validation independence remain unverified. Box and mask metrics are reported separately in `static/model_evaluation.json`.

For a clean CPU environment, install torch/torchvision from the CPU wheel index and `requirements-runtime.txt` as shown in the Dockerfile. The old `requirements.txt` is retained as a historical environment snapshot; it includes CUDA packages that are unnecessary for the CPU deployment.

## Three-minute evaluation

1. Open `/demo` and choose **Field pole inspection**. Run the recorded replay for immediate results.
2. Toggle the detection overlay and inspect individual labels, confidence scores and survey suggestions. Confidence is not independently measured accuracy.
3. Select **Line hardware survey** to inspect a more complex capture. Optionally run live inference or upload a JPG/PNG/WebP (10 MB / 20 MP maximum).
4. Save a needs-review/approved decision and reviewer note. These are isolated demo decisions, not production approval or training changes.
5. Open `/map` to explore eight clearly labeled fictional demonstration poles around Vijayawada–Guntur, Andhra Pradesh. If you know an actual inspection's location, enter both GPS coordinates in its review. Your session locations form a separate layer and GeoJSON export; fictional sample poles are never saved into your inspection records.
6. Reset the demo to delete your session's completed inspections and uploads.

| Training data | Explained | Export corrected YOLO annotations; no demonstrated automatic improvement |

## Architecture

```text
Browser → Flask public pages + evaluation API → SQLite demo job/review store
                              ↓ lazy, serialized inference
                         local YOLO model stack → survey rules → JSON/CSV/GeoJSON

Authenticated /workspace → existing image/video/survey/admin routes → PostgreSQL
                         → optional Azure OpenAI / PlantNet
```

The public model stack uses pole_best6.pt, channel_12class_v2.pt, insulator_new.pt, shed_model.pt and cable_best.pt. Video selection runs before per-pole component analysis. Recordings are reproducible evidence, not a benchmark or independent validation dataset. Photo coordinates are not inferred. Single-image distance/voltage suggestions need field verification; they must not determine electrical safety clearance.

Pole acceptance requires at least **80% model confidence**, including main and strut poles. Lower-scoring or missing-score pole candidates cannot trigger an automatic pole survey; other component classes retain their own thresholds. The deployment cutoff is distinct from saved checkpoint validation metrics, which have not been re-evaluated at that cutoff. Replay provenance records the threshold used. Older results that violate the rule require a new inspection before display, export or mapping.

Demo jobs are scoped to signed browser sessions, stored outside static files, and expire after 24 hours; expired files are cleaned on the next job creation. Reset deletes completed jobs immediately. Signing out or losing cookies loses access to that session's jobs. Live inference has bounded queue capacity and per-session/IP limits. Run one application process; the legacy video queue is process-local and is not a distributed durable worker system.

## Full workspace and deployment

See [deploy/DEPLOYMENT.md](deploy/DEPLOYMENT.md) for Docker, PostgreSQL, administrator provisioning, Namecheap DNS and HTTPS. Local workspace requires `WORKSPACE_ENABLED=true`, PostgreSQL settings, and the runtime dependencies; `/workspace` is then authenticated. Predictable default users are no longer seeded. Public `/demo_login` opens the isolated evaluator rather than impersonating a shared production user.

## Verification

```powershell
pip install pytest
python -m pytest tests/test_pole_classifier.py tests/test_pole_autofill.py -q
```

The legacy `test_survey_storage.py` writes to configured storage and is deliberately excluded from this isolated test command. Use a disposable database before running it. Deployment requires a network-capable machine to download Docker images and Python packages.

The source-only test command above covers survey classification and autofill rules. Some evaluator and confidence tests import the full workspace pipeline and require runtime dependencies and the separate weights. Full live inference, video and database workflows require the separate runtime and weights; see [models/README.md](models/README.md).
